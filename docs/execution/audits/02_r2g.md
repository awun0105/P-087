## Kết luận trước

> **R2G rất đáng dùng để giảm lượng code ở `EX-SCENE`, đặc biệt `2D masks → 3D object identity → per-object point cloud → object-aware Gaussian`. Nhưng R2G hiện không phải một end-to-end implementation đủ hoàn chỉnh để thay pipeline của chúng ta.**

So với OpenReal2Sim:

```text
                    OpenReal2Sim        R2G
EX-REC                 Medium           Medium
EX-SCENE               Medium           VERY HIGH
EX-SIM                 VERY HIGH        Very Low
EX-PRODUCT              Low             None
```

Vì vậy hai repo bổ sung cho nhau khá đẹp:

```text
OpenReal2Sim
→ donor chính cho EX-SIM

R2G
→ donor chính tiềm năng cho EX-SCENE
```

Baseline hiện tại của chúng ta đã đánh dấu R2G là Tier-0 system reference cho per-object Gaussian/point-cloud/mesh/label contracts. Sau audit code, nâng nó thành **Tier-0 Algorithm/Artifact Donor cho EX-SCENE**, không chỉ là reference.

## 2. Thành phần đáng giá nhất: SAMPro3D

Đây là phần **có khả năng giảm nhiều code tự viết nhất của EX-SCENE**.

Pipeline hiện tại của chúng ta đang dự kiến:

```text
SAM2 masks
+
Camera Poses
+
Canonical Geometry
        ↓
MultiViewObjectAssociator
        ↓
Candidate Object Identities
```

và docs hiện nói phần 2D → 3D association sẽ do team tự code. SAMPro3D đã implement gần đúng bài toán đó.

### Code đáng lấy

Các hàm quan trọng:

```text
perform_3dsegmentation()
prompt_filter()
prompt_consolidation()

compute_mapping()
isolate_on_pred()
isolate_on_score()
merge_common_values()
```

Đường logic của họ:

```text
3D point
+
Camera Pose
+
Camera Intrinsics
+
Depth
        ↓
project 3D → image
        ↓
check visibility / occlusion
        ↓
2D mask membership
        ↓
accumulate score over views
        ↓
point ↔ instance probability
        ↓
DBSCAN remove isolated noise
        ↓
merge overlapping prompts
        ↓
3D object IDs
```

Đây gần như chính là vấn đề `MultiViewObjectAssociator` của chúng ta.

## 3. Phần projection 2D ↔ 3D rất đáng port

SAMPro3D có:

```python
compute_mapping(points, data_path, frame_id)
```

Logic:

```text
canonical 3D points
↓
world → camera transform
↓
project bằng fx/fy/cx/cy
↓
image-bound test
↓
depth test
↓
occlusion test
↓
(pixel_y, pixel_x, visible)
```

Sau đó:

```text
mask[pixel_y, pixel_x]
```

để xác định point đó thuộc object nào.

### Ứng dụng cho Real2Sim Studio

Có thể chuyển thành abstraction riêng:

```text
MultiViewProjectionService

project_geometry(
    geometry,
    camera_pose,
    camera_intrinsics,
)
→ VisibleGeometryProjection
```

sau đó association:

```text
SAM2MaskArtifact
+
VisibleGeometryProjection
        ↓
ObjectAssociation
```

Điều này giảm đáng kể code algorithmic phải tự viết.

## 4. Nhưng không được copy nguyên `compute_mapping()`

R2G/SAMPro3D có nhiều assumption hard-code:

```text
depth_shift = 1000
visibility threshold = 0.1
frame_%05d
.tif depth
specific axis flip
specific transforms.json semantics
```

Ví dụ họ thực hiện `R_edit = diag(1, -1, -1)` để convert coordinate convention.

Trong project chúng ta, canonical coordinate phải là source of truth và conversion chỉ được xảy ra ở adapter boundary.

Do đó:

```text
SAMPro3D algorithm
        ↓ ADAPT
our coordinate contract
```

chứ không copy nguyên file chạy trực tiếp.

## 5. Một khác biệt lớn: SAMPro3D cần depth

R2G dùng:

```text
RGB
+
per-frame depth
+
camera poses
+
dense point cloud
```

Trong khi primary RGB path của chúng ta hiện là:

```text
COLMAP camera poses
+
OpenMVS canonical mesh
+
Brush visual
```

Do đó association adapter của chúng ta cần một trong hai cách:
1. **Canonical mesh** → render/project depth từ viewpoint.
2. Hoặc nếu ReconstructionBundle có valid depth artifact: **`DepthFrameSet`** → dùng trực tiếp.

Điều này không làm thuật toán SAMPro3D vô dụng, mà chỉ có nghĩa: **Reuse phần voting/association/consolidation, nhưng thay data adapter.**

## 6. `prompt_consolidation()` rất đáng lấy

Sau khi mỗi point có score cho các candidate object, SAMPro3D không chỉ `argmax`.

Nó làm:

```text
per-point scores
↓
DBSCAN spatial consistency
↓
remove isolated fragments
↓
compare overlap giữa candidate instances
↓
merge candidates đang mô tả cùng object
```

Đây là phần dễ bị chúng ta tự viết lại một cách kém ổn định. Có thể map thẳng vào:

```text
SAM2 proposals
↓
MultiViewObjectAssociator
↓
candidate groups
↓
Merge suggestions
↓
Human Object Confirmation
```

Tức là máy đưa:

```text
object candidate #17
object candidate #42
→ likely same physical object
```

rồi human vẫn có thể Confirm / Merge / Ignore / Reassign theo đúng chuẩn HITL.

## 7. Per-object point cloud đã có

R2G/SAMPro3D xuất segmentation thành từng object:

```text
models/
└── point_cloud/
    ├── obj_00001.ply
    ├── obj_00002.ply
    └── ...
```

README mô tả cả:

```text
models/
├── gaussians/
├── point_cloud/
├── mesh/
└── label/
```

Đây là artifact structure rất gần `SceneObject` của chúng ta:

```text
SceneObject
├── visual_ref
├── geometry_ref
├── collider_ref
├── transform
└── provenance
```

Tức có thể map:

```text
R2G obj_00001 Gaussian     → SceneObject.visual_ref
R2G obj_00001 point cloud  → SceneObject.geometry_ref
```

Nhưng format R2G **không được trở thành canonical SceneIR**. Ta chỉ dùng nó như producer output rồi normalize:

```text
R2G-style artifact
        ↓
SceneObjectAdapter
        ↓
SceneIR
```

## 8. Caveat: Mesh output trong README chưa chứng minh bằng code

README nói `models/mesh/obj_*.ply`, nhưng trong implementation, `get_output_for_asgs.py` chủ yếu tách và ghi **point cloud per object**. Không có implementation hoàn chỉnh trong R2G root cho: `global mesh + instance segmentation → per-object mesh`.

Hiện bằng chứng mạnh hơn là: `2D segmentation → 3D segmentation → per-object point cloud → OBB → per-object GS`. Phần mesh vẫn cần adapter riêng hoặc tận dụng OpenMVS geometry của chúng ta.

## 9. Assist-GS — Visual Decomposition

`assist-gs` dùng Nerfstudio/gsplat và tạo:

```text
background_model
+
object_1_model
+
object_2_model
+
...
```

không phải một global Gaussian cloud duy nhất.

Code trong `AssistGSModel.populate_modules()` tạo `background_model`, `object_models["object_1"]`, ... và seed từng model bằng các point nằm trong object OBB. Sau đó export `background_model.ply`, `object_1.ply`, ...

Đây thực chất là: **object-level Gaussian decomposition đã được implement.**

## 10. Nhưng Assist-GS xung đột với Brush baseline

Visual P0 hiện tại của chúng ta:

```text
COLMAP → Brush → global 3DGS
```

Trong khi R2G:

```text
dense geometry + object boxes + Nerfstudio + gsplat → Assist-GS → background GS + individual object GS
```

Nếu adopt Assist-GS đầy đủ, chúng ta đang đổi backend sang Nerfstudio + gsplat. Chưa nên làm vậy cho P0.

### Cách tận dụng Assist-GS:
- **P0**: Lấy ý tưởng/code nhỏ: per-object OBB generation, Gaussian export format, background/object representation, naming; giữ Brush = primary Visual.
- **P1 / Fallback**: Nếu việc lấy object subset từ global Brush Gaussian quá khó, tạo optional backend:
  ```text
  ObjectVisualBackend
  ├── BrushSubsetBackend
  └── AssistGSBackend
  ```

## 11. `get_aabb.py` đáng reuse trực tiếp

Assist-GS có utility:

```text
per-object point cloud
↓
Open3D minimal oriented bounding box
↓
center, dimensions, rotation, instance_id
```

Output: `[x y z]`, `[h w l]`, `[R 3×3]`, `[instance_id]`.

Map rất đẹp tới: `SceneObject + ColliderSpec + local_frame`. Tuy nhiên OBB của segmentation geometry chỉ là **candidate collider**, sau đó vẫn qua EX-SIM collider policy và validation.

---

## 12. Cutie — Ít giá trị hơn đối với chúng ta

R2G sử dụng Cutie để propagate segmentation qua video. Nhóm đã khóa **SAM2**, vốn cũng hỗ trợ video mask propagation.

Do đó **không thêm Cutie vào P0**. Chỉ tham khảo mask ID persistence và propagation workflow; coi Cutie là fallback nếu SAM2 gặp blocker.

---

## 13. GPT-4 label pipeline: Không nên lấy

R2G có `gpt4_methods.py` gửi image + mask lên OpenAI và hỏi mass, collider, physics. Code upload ảnh lên `sm.ms` trước khi gửi URL.

**Tuyệt đối không dùng cho Real2Sim P0**:
- Vi phạm nghiêm trọng privacy / data boundaries (upload ảnh ra server bên thứ ba).
- Không để LLM hallucinate ra mass, collider, physics cho scene validation.
- AI nếu có chỉ gợi ý semantic label cho Human Confirmation, không quyết định physics truth.
